# Проверка

## Суть

После правки документов — скрипт проекта, одна команда, код выхода 1 при находках (её можно поставить в хук или CI).
Он держит правила метода, которые человек и агент забывают: битые ссылки, упоминания текстом, понятия вне карты.
Как написать — [[Скрипт проверки]].

## Правила

Скрипт проверяет:

- каждая ссылка ведёт на существующий документ, каждое понятие есть на карте, у каждого — «Суть»;
- каждый якорь (`#Раздел`, `#^метка`) ведёт на существующий раздел или метку;
- нет неоднозначных ссылок — `[[Имя]]` при двух документах с этим именем;
- ссылка не разорвана переносом строки; на документы нет ссылок Markdown — только ссылки Obsidian ([[Ссылки]]);
  ссылка Markdown без схемы (`[текст](путь)`) ведёт на существующий файл — иначе в графе фантомный узел;
- упоминаний документов текстом нет (решение, находка, этап по номеру, путь к документу, имя понятия, раздел рядом со
  ссылкой); скрипт умеет сам сделать их ссылками; имя у двух документов — списком;
- у каждого документа есть `type`, `description`, `project` и ключи своего вида; значения `type` и `status` — из
  списков ([[Шапка документа]]);
- пути из `paths` существуют; код, которого нет ни в одном `paths`, — списком;
- документы, у которых код из `paths` менялся после коммита из `verified`, — списком «возможно, устарели»;
- у понятия `status` совпадает с тем, пуст ли раздел «Открыто»;
- у закрытой находки есть `verified_by` (`resolved`), причина (`rejected`) или решение в `decisions` (`accepted`); у
  `blocked` из-за решения — `decisions`; у открытой пути из `paths` существуют;
- на каждое действующее [[Решение|решение]] ссылается `decisions` понятия, методология, план или процедура;
- документы-сироты — без единой входящей ссылки, от карты до них не дойти, — списком (справочно: история бывает
  сиротой законно, её не считают).

Нет скрипта — хотя бы поиск старого имени после переезда файла.
